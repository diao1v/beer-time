# Adding & changing GIFs (celebrations + idle background)

Two GIF/PNG slots exist on the panel:

1. **Celebration animations** — played for ~10 s when a Jira event fires (panda2, david, etc.).
2. **Idle clock background** — looping bg behind the clock when nothing's happening.

Both use the same converter (`tools/gif_to_rgb565.py`) driven by a manifest, plus the auto-generated registry header that `main.cpp` includes. **`main.cpp` is never edited when adding/removing animations.**

For shipping the change to a live panel, see [`docs/ota.md`](./ota.md) — the short version: push a `v*` git tag and the panel auto-updates within ~60 s.

---

## End-to-end flow

```
local: drop gif into tools/gifs/
       edit tools/animations.json
       python3 tools/build_animations.py   ← regenerates .h files + _registry.h
       git commit + push                    ← just code, no release yet
       git tag v0.x.y && git push origin v0.x.y
                                              │
                                              ▼
CI:    build firmware.bin (FIRMWARE_VERSION = tag)
       upload firmware.bin + manifest.json to Cloudflare R2
       publish MQTT trigger to HiveMQ
                                              │
                                              ▼
panel: receives trigger → fetches manifest → version differs →
       downloads firmware.bin → applies → reboots → shows green "OTA OK"
```

Total time from tag push to panel running new code: usually 30–60 s.

## TL;DR — add a new celebration

1. **Drop the source** (`your.gif` or `your.png`, 64×64) into `tools/gifs/`.
2. **Add a row** to `tools/animations.json`:
   ```json
   { "kind": "celebration", "name": "myanim", "source": "your.gif", "args": [] }
   ```
3. **Regenerate locally:**
   ```bash
   cd led-panel-firmware
   python3 tools/build_animations.py
   ```
   That writes `include/animations/myanim.h` and updates `include/animations/_registry.h`.
4. **Commit + push:**
   ```bash
   git add tools/animations.json include/animations/myanim.h include/animations/_registry.h
   git commit -m "add myanim celebration"
   git push
   ```
5. **Tag a release** to ship to the panel:
   ```bash
   git tag v0.x.y && git push origin v0.x.y
   ```

Trigger via MQTT (`myanim`, or `myanim-ws` to force the rotating star border).

## TL;DR — change the idle background

Same as above but use `"kind": "idle_bg"` and `"name": "clock_bg"`:
```json
{ "kind": "idle_bg", "name": "clock_bg", "source": "bg5.gif", "args": [] }
```
Only one entry should be named `clock_bg`. Overwriting the source/entry swaps the bg.

## TL;DR — avatar-style portrait (white circle, inset for star border)

```json
{
  "kind": "celebration",
  "name": "marcel",
  "source": "marcel.png",
  "args": ["--bg-key", "255,255,255", "--circle-bg", "255,255,255", "--inset", "6"]
}
```

`--inset 6` shrinks the content into a 52×52 region so the rotating star border doesn't overlap. `--bg-key "255,255,255"` zeroes the white PNG background. `--circle-bg "255,255,255"` paints a centered white circle as the avatar's backing.

## Manifest fields

`tools/animations.json` is a flat array. Each entry:

| Field | Purpose |
|---|---|
| `kind` | `celebration` or `idle_bg`. Drives where the entry ends up in the generated registry. |
| `name` | C identifier and MQTT trigger name (e.g. `panda2`). What `DEVELOPER_ANIMATION_MAP` maps to. |
| `source` | Filename inside `tools/gifs/` (`.gif` or `.png`). |
| `args` | Extra flags forwarded to `gif_to_rgb565.py` (avatar circle/inset, etc.). |
| `optional` | If `true`, build skips the entry when the source file is missing. Useful for animations whose `.h` is committed but whose source isn't (e.g. existing avatars). |
| `note` | Free-form comment; documentation only. |

## The generated registry header

`include/animations/_registry.h` is regenerated by `build_animations.py`. It contains:

- `#include "animations/<name>.h"` for every manifest entry (celebrations + idle_bg).
- A `drawX` wrapper function for every `celebration` entry.
- A macro `ASSET_ANIMATION_ENTRIES` that expands to the `{ "name", drawX, true }` rows used inside `main.cpp`'s `ANIMATIONS[]`.

`main.cpp` references the macro like this:
```cpp
#include "animations/_registry.h"   // after drawGifFrame is defined
...
static const Animation ANIMATIONS[] = {
  { "fireworks", drawFireworks, false },   // ANIMATIONS[0] = default fallback
  { "rainbow",   drawRainbow,   false },
  { "hearts",    drawHearts,    false },
  { "confetti",  drawConfetti,  false },
  ASSET_ANIMATION_ENTRIES
};
```

Procedural animations (`rainbow`, `fireworks`, `hearts`, `confetti`) are hand-coded — they don't fit the manifest pattern. `ANIMATIONS[0]` is the unknown-name fallback (currently `fireworks`).

**`_registry.h` is committed.** A fresh clone can `pio run` without first running the Python script.

## Source requirements

| Property | Required | Why |
|---|---|---|
| Dimensions | **64×64** | Panel size. Converter rejects mismatches. |
| Transparent background | strongly recommended | Lets the alpha channel handle bg removal cleanly. Opaque sources need `--bg-key`. |
| Frame count | any | More frames → bigger firmware. ~8 KB per frame. |
| Frame delays | any | Honored at playback. Very low delays (0 or 10 ms) are clamped to `--min-delay` (default 30 ms). |

### Where to find gifs

- **[Tenor](https://tenor.com/)** — large library; search "celebration", "panda", "fireworks".
- **[Giphy](https://giphy.com/)** — use the "Download" button.
- Pixel-art sprite GIFs render best on 64×64 LEDs.

### Resizing to 64×64

Most gifs are 200×200+. Resize first.

1. Open in **[ezgif.com → Resize](https://ezgif.com/resize)**.
2. Width and height both **64**.
3. Method: **Nearest neighbor** for pixel-art look; **Lanczos** for smoother detail.
4. Save and drop into `tools/gifs/`.

Non-square source? Use ezgif's **Crop** first, then resize.

## Converter flags

`tools/gif_to_rgb565.py` (used indirectly via the manifest):

| Flag | Default | Use |
|---|---|---|
| `--name` | required | C identifier prefix. The manifest supplies this from the `name` field. |
| `--width` / `--height` | `64` | Panel dimensions. |
| `--min-delay` | `30` | Floor for per-frame delays in ms. |
| `--bg-key` | (alpha only) | `"R,G,B"` to zero pixels matching that color (for opaque sources). |
| `--bg-tolerance` | `24` | Max per-channel distance from `--bg-key` to also zero. |
| `--circle-bg` | (off) | `"R,G,B"` to paint a circular bg behind the subject (avatar style). |
| `--inset` | `0` | Shrink content by N pixels on each side so it fits inside e.g. a star border. |

Put these in the manifest's `args` array.

## Flash & partition considerations

Each 64×64 RGB565 frame is **8 192 bytes** of flash.

| Frames | Flash per animation |
|---|---|
| 1 (static avatar) | 8 KB |
| 7 | 56 KB |
| 22 | 176 KB |
| 97 | 776 KB |

`platformio.ini` uses a custom partition table `partitions_ota.csv` giving two 1984 KB app slots (dual-OTA). Current firmware fits with a little headroom. If you blow past it, the build fails with `region '...' overflowed`. Options:

- Use a shorter idle background (the biggest contributor by far — 97 frames = 776 KB).
- Drop unused avatar `.h` files (small wins).
- Reduce panda2/etc to fewer frames via ezgif's "Optimize" tool.

## Removing an animation

1. Remove its row from `tools/animations.json`.
2. Delete `include/animations/<name>.h`.
3. (Optional) delete the source from `tools/gifs/`.
4. Run `python3 tools/build_animations.py` — `_registry.h` is regenerated without it.
5. Update any `DEVELOPER_ANIMATION_MAP` entries that referenced it in `led-notifier/.env` (otherwise they'll fall back to `fireworks`).
6. Commit + push + tag a release.

## Discovery mode (hardware debugging)

A separate PlatformIO env `discovery` boots the panel, skips WiFi/MQTT, and loops a single hardcoded animation. Useful when iterating on:
- A new gif's converter output
- Panel hardware tuning
- Rendering bugs

```bash
pio run -e discovery -t upload
pio device monitor -e discovery
```

To swap which animation plays, edit the body of:
```cpp
#ifdef DISCOVERY_MODE
  drawDavid(t);        // <-- swap to your animation
  drawStarBorder(t);
  panel->flipDMABuffer();
  return;
#endif
```

## Celebration duration

`src/main.cpp`:
```cpp
const uint32_t CELEBRATE_MS = 10000;   // 10s per celebration
```

The gif's own length is independent — short gifs loop more times within the celebration window; long gifs play through fewer times.

## Lessons learned (post-mortem)

Three issues hit while bringing up the gif pipeline. All looked like "ghosting" or "residue" but had different root causes.

| Symptom | Root cause | Fix |
|---|---|---|
| Every previous frame's pixels stayed lit indefinitely | Converter used a running canvas (`paste(rgba, mask=alpha)`) that accumulated frames. Frame N's stored data contained frames 0..N composited. | Trust PIL: `src.seek(i); src.convert("RGBA")`. Disposal handled automatically. |
| Panda body was wiped out, leaving only stripes/outlines | Auto-detected the gif's transparent-fill color as "the background" and zeroed it — but the color happened to match the panda's body. | Use the alpha channel instead of color matching. `alpha < 128 → 0x0000`. |
| Two pandas visible at once / mid-frame tearing | `drawGifFrame` was called every `loop()` iteration, re-blitting 4096 pixels into the live DMA buffer while the panel scanned. | Frame-skip + double-buffering (`mxconfig.double_buff = true` + `flipDMABuffer()`). |

When iterating on a new gif, sanity-check the generated header's byte count and the proportion of `0x0000` entries. Constant size across frames + count roughly equal to `frames × transparent_pixels` means the converter is producing clean output.
